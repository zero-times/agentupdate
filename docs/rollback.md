# 一键回滚（AGE-10）

成功更新、待恢复和恢复失败事务可以回滚。后端只接受持久化事务 ID，验证该事务恢复点的身份、清单和所有包/配置载荷；核对标准 npm 路径、目录所有者及权限、配置根和工具占用。恢复不依赖网络或 npm，使用原实例的 Node 在隔离环境验证重建旧版本、架构和 --help。

更新后配置有变化时，界面必须明确确认；后端先在恢复点 `rescue/<attempt>/` 保存当前受管配置及清单，再复核准备期间没有新改动。只有完成上述准备后才落盘 recovering。将当前工具包保留为 `.agentupdate-displaced-<attempt>`，发布旧包及原启动链接，只恢复受管配置，核验内容、文件/目录权限、链接、原始缺失状态、实际命令路径、版本和健康检查后才记录 restored。无关新文件保留。任何发布或验证失败记录 recovery_failed，保留全部材料。

自定义配置根仍受适配器边界约束；注入的测试 HOME 不继承真实用户配置目录变量。受管配置链接祖先只记录目录权限，不递归捕获无关文件。目录或特殊文件类型冲突不会被自动删除。

## 验证

真实隔离 Codex 0.162.0 → 0.162.1 → 0.162.0、Gemini 0.62.0 → 0.63.0 → 0.62.0 全部通过生产服务。恢复后的旧安装全树与升级前快照一致，改动配置先保存，原配置恢复，新凭据的原始缺失状态恢复，无关文件保留。制品来自先前官方 npm 缓存并重新校验官方 URL/SHA-512。本次不依赖在线下载，也未改变日常 Agent。可复现脚本：`scripts/validate-update-workflow.mjs roundtrip`；证据：`docs/evidence/age-10-rollback.json`。

故障测试覆盖损坏载荷、越界配置链接、配置变化确认、原目录缺失、权限恢复以及配置类型冲突。类型冲突发生在实际恢复阶段，结果明确为恢复失败，恢复点与冲突目录内容均保留，不误报成功。

## 人工处理

1. 停止对应 CLI 的运行进程，关闭 AgentUpdate 后先复制整个应用数据目录，保留 state.sqlite3/WAL、restores、recovery-work 以及 npm 包旁的保留目录；不要在恢复失败时清理材料。
2. 若受管配置被改成目录，先将该目录完整移到受管范围之外，保留其内容；修正目录权限或原配置根设置后，重新打开应用并重试该事务回滚。应用先保留当前配置，完整离线校验旧版本后恢复。
3. 若恢复点损坏，不从损坏载荷强行恢复。保留损坏恢复点与 `.agentupdate-old-<transaction>` / `.agentupdate-displaced-<attempt>`，对照 manifest.json 的 originalVersion、packageRoot、launcherLink 和文件校验值核实可用旧包。仅在工具已停止且路径核对完成后，由管理员将核验后的整包置回 manifest 指定的 packageRoot，并重建 launcherLink；不要覆盖共享 npm prefix。
4. 配置载荷按路径哈希命名，manifest 的 config.entries 记录原路径、模式、链接和 SHA-256。必须逐文件核验并保留现配置后才能人工重建；不将 rescue 或原始配置上传到日志/看板。人工处理不能自动把数据库状态改成 restored，应重新通过应用验证或留下失败记录。

按用户要求保持进行中，整个版本完成后统一审核。
