后端接收持久化事务 ID，不接受任意命令、安装路径或 tarball 输入。前端先通过官方版本服务固定目标。预检重扫具体实例，核对来源、旧版本、Node/架构、路径与用户权限，检查运行中的对应工具和空间。桌面应用内置 Codex 不会阻挡不同的用户 npm 实例。

强制备份完成后，在应用私有目录下载并校验固定官方 tarball 的 SHA-512，或核验此前完整缓存的同一制品。npm 使用已发现 Node.js 配套 npm、明确参数数组、独立 HOME/空 user/global npmrc、官方 registry、忽略生命周期脚本及受限写入范围。构建隔离 global prefix，先验证新命令版本、架构、--help 和依赖树。启动检查禁止网络和真实配置读取，不触发推理或登录。

安装前再检查占用、实例、旧包全树和配置是否变化。所有准备错误记录 preparation_failed，实际安装不变。事务先持久化 installing，再在原包所在文件系统重建替换树；仅移动该工具包，不覆盖整个共享 prefix。旧包移至与事务绑定的保留目录，再发布新包和命令链接，同步目录。verifying 核对实际命令属于此包、版本/架构与 --help；之后才记录 succeeded。任意修改或验证失败记录 needs_recovery，保留恢复材料。

`execute_update` 在独立后台工作中执行，历史读取可持续显示已提交的阶段。暂有应用内操作互斥；批量和跨进程实例锁由后续任务加固。
