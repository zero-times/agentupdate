## 本轮修正与复验

- 补入隔离 PATH 的 `/usr/sbin` 和 `/sbin`：Gemini 的 x64 架构检查依赖 `sysctl`，原环境导致误判检查失败。新增真实系统命令回归测试先失败再修复。
- 子进程组改用 Rust `CommandExt::process_group(0)`，允许 macOS 采用 `posix_spawn`，保留整组超时回收，避免多线程桌面进程中的 `pre_exec` fork。
- 真实全新 Codex x64 依赖的隔离冷启动实测 31.121 秒，原 12 秒探测预算不足。x64 工具启动预算调整为有界 60 秒；Node 和 arm64 探测仍为 12 秒。候选扫描总预算改为 120 秒，避免第一个冷启动使第二种工具被跳过；隔离规则和超时终止不变。
- UI 验收增加实际执行架构与两项事务数量断言，防止把错误架构或空结果误记为通过。
- 前端自测入口仅在专用 `desktop-validation` 构建模式中引入；正式前端构建不包含自测 JS。Rust 自测命令仍仅由专用 feature 编译，并使用独立验证包。
- 生产构建清理验证构建遗留的三份自动生成权限声明，防止开发命令名称留在生产 ACL 元数据中；最终包同时检查主窗口授权、前端资源和命令名称。
- 清理 README、旧阶段文档、扫描时限和数据库 schema 的过时说明。
- 两种架构均通过实际 React/WebView 的两工具选择、计划确认、更新、回滚、脱敏导出、最新恢复点保护和应用更新提示。两项事务均为 `restored`，原安装全树和人工配置与更新前一致。证据：`age-15-ui-arm64.json`、`age-15-ui-x86_64.json`。
- 最终构建、测试数量、故障复验和架构结果以 `docs/evidence/v0.1.0-audit.json` 为准。Rosetta 结果明确限定本机验证，不等于物理 Intel 验收。

最终结果：前端类型检查/生产构建与 Rust 格式检查通过，后端 43 项常规测试通过；真实两工具安装/验证故障、恢复失败后重试和原包全树恢复复验通过。生产通用 `.app` 为 0.1.0 / macOS 15.0，两个切片和签名完整性通过；三个开发命令与六项故障/目录/离线/工作流注入标记均不在该二进制中，前端自测模块也已剔除。诊断脱敏拒绝名单保留结果环境变量的名称，不启用生产自测接口。该包仍为 ad-hoc，未公证、未制作正式安装 DMG。原始结果见 `age-15-production-bundle.json` 和汇总证据。
