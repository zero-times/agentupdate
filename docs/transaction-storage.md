# 事务与恢复点存储（AGE-7）

macOS 数据位于当前用户的 `Library/Application Support/AgentUpdate`。SQLite 保存实例快照、固定目标制品、计划、逐项阶段、恢复点引用与事件；配置和制品放在独立恢复目录。目录 0700，普通文件 0600，拒绝最终数据路径的符号链接和不正确所有者。不向前端开放数据库、阶段转换或任意路径操作。

SQLite 采用 WAL、FULL synchronous、外键、5 秒忙等待。当前 schema 为 2；旧版本在事务中依次迁移，schema 2 增加持久化取消请求，较新版本拒绝降级。打开前核对文件头，打开后 quick_check；损坏时保留原文件，拒绝自动删除重建。读取时交叉验证 JSON 与阶段/实例/计划/恢复引用列，字段矛盾不能作为成功记录。

计划固定后端已扫描的受支持实例和官方校验的版本，前端仅提交实例 ID、目标版本与预发行选择。最多 32 项，重复实例或存在未完成事务时拒绝新计划。

## 文件与数据库的提交协议

1. 先记录 preflight / backing_up。材料建立于 `restores/<UUID>.partial`。
2. 完整写入并同步配置、旧制品及清单。清单绑定事务、实例、原版本和目标版本。
3. 同步目录，原子重命名为 `restores/<UUID>`，同步父目录。
4. SQLite 单事务提交恢复点引用、清单 SHA-256、prepared 阶段和事件。

中断留下 partial 或未引用的完整目录时，不能进入 installing。文件发布后数据库提交失败，保留孤立材料以供检查。正式材料内容校验由备份服务执行；此层负责清单身份、哈希及引用一致性。installing、verifying、recovering 原样持久化，不在重启时推测成功。安装与恢复前重新校验恢复点所属事务和清单。

事件不存储配置内容或原始进程输出。事件 ID 与事务 ID 构成诊断记录引用；后续日志导出从事件生成脱敏内容。

## 验证

`transaction_storage.rs` 覆盖重开后安装中阶段、重复实例、非法转换、过期 CAS、缺失/暂存/损坏材料、清单哈希、迁移、较新数据库拒绝、损坏文件保留及 JSON/列矛盾。仅使用临时应用目录。常规 Rust 测试通过，前端类型检查通过；真实安装修改由后续闭环验证。
