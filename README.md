# AgentUpdate

AgentUpdate 是一个桌面应用，用于集中管理本机 AI Agent 工具的版本。用户可以选择多个工具，一次更新到指定版本或最新稳定版；应用默认在修改前备份配置，并在升级失败时提供一键回滚入口。

下载当前版本：[GitHub Releases](https://github.com/zero-times/agentupdate/releases/latest)。v0.2.2 提供 macOS 15+ 的 Apple Silicon / Intel 通用 DMG 和应用 ZIP，并附带 SHA256SUMS。安装包采用 ad-hoc 完整性签名，未完成 Developer ID 签名与 Apple 公证。

v0.2.1 重新设计了工作台：侧栏分别进入 CLI 工具、桌面应用和本应用更新，保留安装、升级、备份与恢复能力。可从 v0.2.0 通过“检查应用更新 → 下载更新并安装重启”测试在线升级；[新版界面与测试说明](docs/v0.2.1-ui.md)。

项目优先支持 macOS，随后扩展 Windows 和 Linux。v0.1.0 已实现工具发现、版本选择、强制备份、单项与批量更新、回滚、崩溃恢复、历史管理和自身版本检查。2026-10-13 追加修复 Codex CLI 本机版本读取，支持 Claude Code CLI 一键升级，以及 Codex、Claude、ChatGPT 桌面应用更新检测。当前本地使用与审核接受无 Developer ID 签名的候选包；独立 Intel/macOS 15 验收与正式签名公证仍如实记录。最新结论见 [版本完成情况检查](docs/v0.1.0-readiness.md) 和 [实施记录](docs/implementation-progress.md)。

当前新增版本 v0.2.0 已补齐 Codex / Claude / Deepseek / Gemini CLI 的安装入口、Codex Homebrew 升级、用户所有的本机 npm 更新、Codex / Claude / ChatGPT 应用安装与恢复，以及 AgentUpdate 自身在应用内下载安装并重启。操作方式和准确支持范围见 [v0.2.0 安装与升级说明](docs/v0.2.0-install-and-update.md)；新增版本验收见 [v0.2.0 审核材料](docs/v0.2.0-readiness.md)。下方“首期”保留 v0.1.0 的原始规划，v0.2.0 以新增说明为准。

阶段 1 成果：

- [Agent 支持矩阵与恢复实验](docs/agent-support-matrix.md)：Codex CLI、Gemini CLI 的隔离 npm 安装、升级与离线恢复通过。
- [桌面技术验证](docs/desktop-technology-validation.md)：Tauri 2 通用实验包、Apple Silicon 原生 / Intel Rosetta 运行，以及实际 WebView 权限验证通过。
- 可复现脚本位于 `scripts/`，最小桌面实验位于 `experiments/desktop-spike/`。
- [macOS 发布材料](docs/macos-release.md)与[使用和恢复说明](docs/macos-v0.1.0-usage.md)已编写；实际制品和验收以最新完成情况检查为准。

## 产品目标

- 在一个界面中查看已安装 Agent、当前版本、安装来源和可用版本。
- 支持单个更新与批量更新，并允许为每个 Agent 选择不同的目标版本。
- 默认备份用户配置，在执行更新前准备可验证的旧版本恢复方式。
- 升级失败后保留诊断信息，支持一键恢复原版本与升级前配置。
- 从项目 GitHub Releases 检查 AgentUpdate 自身的新版本，展示更新说明与安装包入口。
- 通过工具适配器和平台适配器扩展支持范围，避免为每个平台重写业务流程。

这里的 Agent 指用户本机安装的 AI 编程助手及相关命令行工具。首期管理 CLI 更新与恢复，并检测已支持桌面客户端的更新；IDE 插件和远端服务不属于首期范围。

## 首期范围（macOS MVP）

### 工具与安装方式

首批适配对象为 Codex CLI、Gemini CLI 和 Claude Code CLI 的用户可写 npm 实例；Claude 同时支持默认用户原生安装和标准 Homebrew Cask 的最新稳定版更新。Codex Homebrew 来源能读取版本，仍仅展示。具体支持范围和来源差异见 [Claude 与桌面更新说明](docs/claude-and-desktop-updates.md)。

更新前保存完整旧安装，恢复使用本地已验证材料。Claude 原生与 Homebrew 渠道各自查询最新稳定版，不假定 Homebrew 能重新安装任意历史版本。

同一工具可能通过多个来源安装。发现阶段必须识别实际命令路径、安装来源、CPU 架构以及多个安装实例；有歧义时让用户选择要管理的实例，不擅自覆盖其他安装来源。

| 能力 | 首期要求 |
| --- | --- |
| 安装发现 | 显示工具、实际路径、版本、来源、架构与支持状态 |
| 版本选择 | 查询官方可用版本；提供指定版本与最新稳定版，预发行版需明确选择 |
| 批量更新 | 用户选择多个工具，执行前显示每项当前版本、目标版本及恢复准备情况 |
| 配置备份 | 默认开启；首次 MVP 不提供跳过开关，备份失败则停止该项更新 |
| 回滚准备 | 修改前保存旧版本制品或验证等价的恢复来源，不具备条件的实例仅展示信息 |
| 一键回滚 | 使用该次更新的恢复点，恢复旧版本和配置，并核验实际恢复结果 |
| 任务记录 | 展示进度、逐项结果、失败原因、恢复点及可脱敏导出的日志 |
| 应用版本检查 | 启动时后台检查，支持手动检查；从 GitHub Releases 获取稳定版并提供更新说明和安装包入口 |

首期不实现无人值守自动更新、跨设备配置同步、自动修改用户凭据或自动下载安装 AgentUpdate 自身。管理员权限依赖、系统级安装和不明来源的自定义脚本暂不执行更新，界面说明具体原因。

### AgentUpdate 自身的版本更新检查

应用版本发布到当前仓库的 [GitHub Releases](https://github.com/zero-times/agentupdate/releases)。更新服务通过 GitHub Releases API 查询已发布版本，以应用构建版本为当前版本，解析 `vMAJOR.MINOR.PATCH` 标签并按语义化版本比较，不能按字符串或发布时间比较。仅当远端稳定版本严格高于当前版本时提示更新；草稿、预发行版本和无法解析的标签不参与稳定版比较。

- 应用启动后在后台检查，自动检查默认最多每 24 小时一次；“关于 / 检查更新”支持随时手动检查，并显示当前版本、最新版本和最近检查时间。
- 发现新版本时展示版本号、发布时间、更新说明与对应 Release 页面，按当前 macOS 架构提供安装包入口；没有匹配制品时明确说明，不能推荐不兼容包。
- 无发布版本、已经是最新版、本地版本高于远端、检查失败是独立状态。离线、超时、GitHub 限流或权限错误不能显示为“已是最新版”；保留上次结果并标明检查时间。
- 请求采用超时、有限重试、缓存与限流退避；后台检查不能阻塞启动或工具更新任务，不发送本机 Agent 配置、凭据或项目内容。
- 首期用户从对应 Release 获取安装包并手动安装。应用内自动替换安装、静默升级和自身升级回滚另行规划。

发布约定：Git 标签 `v<version>`、应用内版本和 Release 版本保持一致；每个稳定 Release 包含更新说明、签名公证的安装包和 `SHA256SUMS`。制品命名为 `AgentUpdate-<version>-macos-universal.dmg`，独立架构包使用 `aarch64.dmg` / `x86_64.dmg` 后缀；检查服务优先对应架构，再回退通用包。附属归档为真实 `.app.zip`；生成的本地 Release fixture 用于核对解析、链接及双架构匹配，不冒充线上发布。操作步骤与签名、设备阻塞见 [发布材料](docs/macos-release.md)。

## 用户操作流程

1. 打开应用，扫描已安装工具；用户可补充工具路径，并确认存在歧义的安装实例。
2. 选择工具和目标版本。批量操作时，每个工具保留独立的目标版本。
3. 查看更新计划，包括安装来源、配置备份位置、旧版本恢复方式及必要的前置条件。
4. 确认执行。应用逐项完成检查、备份、恢复准备、安装和验证，并持续显示进度。
5. 查看各项结果。失败项提供诊断与一键回滚入口；成功项同样保留恢复点，供之后手动回滚。

更新采用顺序队列，避免同时操作共享包管理器或修改相同目录。一项失败后先暂停队列，由用户选择回滚该项、继续剩余项或结束任务。已成功的项目保留结果，不因后续项目失败自动撤销。

取消操作仅在适配器声明的安全阶段生效；安装中请求取消时，等待安全边界或完成恢复，不能强制终止后宣称系统未被修改。

## 默认备份与一键回滚

### 备份内容

每次更新建立独立恢复点，至少记录：

- 工具标识、安装实例、更新前后版本、安装来源、实际命令路径、平台及架构。
- 适配器已确认的用户配置文件和目录，以及文件权限、校验值与原先不存在的路径。
- 旧版本安装制品或已验证的恢复来源、制品校验信息和恢复步骤。
- 更新事务标识、时间、执行阶段、结果和关联日志。

配置路径必须由适配器确认，并允许用户检查备份清单。符号链接需记录原始链接与受控目标，不能无边界地递归复制。若工具未生成配置，记录“原先不存在”也属于有效快照。用户项目源码不纳入默认备份。

备份保存在当前用户的应用数据目录，按安装实例和事务隔离。macOS 暂定根目录为 `~/Library/Application Support/AgentUpdate/`；Windows 和 Linux 通过平台适配器选择各自标准目录。备份可能含令牌等敏感配置，MVP 采用仅当前用户可读写的权限；不上传原始配置，不在日志中输出凭据。备份加密作为后续增强项。

### 更新事务

`发现 → 预检 → 配置备份 → 旧版本恢复准备 → 安装目标版本 → 验证 → 成功`

预检确认工具未被占用、路径和权限符合预期、磁盘空间充足、目标版本可用、备份范围明确。安装前必须确认配置快照可读取且旧版本可恢复，并把事务阶段持久化。任一准备步骤失败都不得开始修改安装。

安装后同时检查实际命令路径、版本和非破坏性的启动检查。能输出版本号不等于升级成功；具体健康检查由适配器定义，且不能消费付费请求或修改用户项目。

### 回滚规则

1. 失败发生在安装前：标记未修改安装，保留失败原因，无需回滚。
2. 失败发生在安装或验证阶段：标记为“待恢复”，提供该恢复点的一键回滚。
3. 回滚时先检查工具占用与恢复点完整性。若配置在快照后发生变化，先保存当前配置，并提示将恢复到更新前状态，避免静默丢失用户修改。
4. 恢复原版本，再恢复升级前配置、权限及原始缺失状态；只处理适配器声明的受管路径，不能删除无关新增文件。
5. 重新检查版本、命令路径和配置完整性。恢复失败时标记“恢复失败”，保留所有恢复材料及可操作的人工恢复说明，不能显示为已回滚。

同一安装实例同时只允许一个更新或回滚事务。应用退出或崩溃后，下次启动读取持久化记录，识别未完成事务并提供检查与恢复入口，不能直接当作成功或重复执行安装。

历史备份支持查看、导出和清理；至少保留最近一次可用恢复点，不自动清理进行中的事务或仍待恢复的材料。磁盘不足时停止新更新并提示清理，不能为了继续更新删除唯一的恢复点。

一键回滚只对已验证的工具、安装来源和配置范围承诺支持。外部服务状态、用户自行修改的系统文件及未受管数据不属于恢复范围；无法稳定降级的安装方式应显示具体限制，待验证后再开放更新。

## 技术方案建议

采用 **Tauri 2 + React + TypeScript + Rust**：前端实现工具列表、版本选择、进度与历史记录；Rust 层管理本地进程、文件备份、事务和平台能力。阶段 1 已验证最小打包、权限、子进程管理及通用二进制运行；AGE-5 已建立仓库根目录的正式桌面基础工程，首版最低系统设为 macOS 15。运行与构建见 [桌面开发说明](docs/desktop-development.md)。

| 模块 | 职责 |
| --- | --- |
| 桌面界面 | 工具发现结果、更新计划、确认执行、任务进度、恢复点与日志 |
| 更新服务 | 生成计划、顺序调度、实例锁、取消边界及错误处理 |
| Agent 适配器 | 工具发现、官方版本查询、配置定位、更新、验证与旧版本恢复 |
| 平台适配器 | 路径、架构、权限、进程检查及平台差异 |
| 备份服务 | 配置快照、制品保存、完整性校验、恢复与保留策略 |
| 事务存储 | 持久化计划、恢复点、阶段和执行结果，支撑崩溃后恢复 |
| 应用版本检查服务 | GitHub Releases 查询、语义化版本比较、缓存与检查状态、更新说明及架构匹配的安装包入口 |

适配器统一提供 `detect`、`listVersions`、`preflight`、`backupConfig`、`prepareRollback`、`install`、`verify` 和 `rollback` 能力，并声明平台、安装来源、可回滚版本与安全取消阶段。业务层依据能力生成计划，不能将每种工具视为相同的安装方式。

建议以 SQLite 保存工具实例、更新任务、逐项事务与恢复点元数据，配置快照和安装制品单独保存在文件系统。写入阶段与文件落盘之间采用可恢复的事务协议；数据库恢复点引用必须经过完整性校验。

本地命令使用明确的可执行文件及参数数组，不拼接未经验证的 shell 字符串。远端版本和安装制品仅通过适配器认可的官方来源获取，支持超时、有限重试和提供方可用的校验或签名验证。前端只调用受限的业务接口，不开放任意命令执行或任意文件读写。

正式应用目录：

```text
agentupdate/
├── README.md
├── docs/                 # 适配器调研、数据模型、恢复协议与发布说明
├── src/                  # React 界面

│   └── src/
│       ├── agents/       # 各工具与安装来源适配器
│       ├── platform/     # macOS / Windows / Linux 平台实现
│       ├── updater/      # 更新计划、调度和事务
│       ├── backup/       # 快照与恢复

```

## 实施计划与验收

按依赖推进，阶段工期在首批适配器调研完成后估算。

| 阶段 | 交付物 | 验收条件 |
| --- | --- | --- |
| 1. 适配器调研与技术验证 | 官方来源、安装/配置/降级能力矩阵；桌面技术验证；确定首批两种工具 | 两种工具各至少一种安装方式完成指定版本安装、配置备份及原版本恢复实验；记录不支持情况 |
| 2. macOS 应用基础 | 桌面框架、平台层、工具发现、版本列表、事务存储 | 在 Apple Silicon 和 Intel macOS 上准确识别支持实例；多来源冲突与不支持来源有明确提示 |
| 3. 单工具完整闭环 | 更新计划、强制默认备份、恢复准备、安装验证、一键回滚 | 最新稳定版与指定版本均能更新；备份失败不修改安装；安装/验证失败后可恢复版本和配置 |
| 4. 批量操作与恢复加固 | 顺序队列、实例锁、取消、崩溃恢复、历史记录、脱敏日志与应用版本检查 | 混合成功/失败的批量任务逐项可追踪；失败暂停；重启后识别未完成事务并恢复；GitHub Releases 新版本检测与手动检查可验证 |
| 5. macOS 首次发布 | 安装包、签名与公证、GitHub Releases 发布材料、使用和恢复文档 | 两种架构完成安装/更新/回滚冒烟验证；权限、离线、磁盘不足和网络中断路径通过验证；Release 版本、说明与制品匹配，应用更新检测通过验收 |
| 6. Windows / Linux 扩展 | 平台路径、进程与安装来源适配；对应安装包 | 各平台重新验证发现、备份、指定/最新版本更新、批量失败和回滚，不能仅凭编译通过标记支持 |

首期整体完成的标准：用户能在 macOS 上对至少两种已验证工具批量更新，默认备份配置，明确看到逐项结果，并能从失败更新恢复到原版本与升级前配置；同时能检查 AgentUpdate 自身的 GitHub Releases 新版本并获取匹配的安装包。

### 必须验证的故障路径

- 配置备份失败、配置不存在、备份包含符号链接或敏感信息。
- 目标版本不存在、离线、下载中断、制品校验失败或旧版本不可获取。
- 工具正在运行、权限不足、磁盘不足或两个操作竞争同一实例。
- 安装中途失败、实际版本不符、命令路径变化及健康检查失败。
- 应用在安装/恢复阶段退出，重启后识别事务并恢复。
- 批量任务部分失败、用户取消，以及回滚后配置权限与原始缺失状态恢复。
- 配置在更新后被修改、恢复点损坏或回滚再次失败，结果不能误报成功。
- 应用版本检查遇到无 Release、预发行/无效标签、版本相等或倒退、`v0.9.0` 与 `v0.10.0` 比较、缺少匹配安装包、离线、限流或异常响应，不能误报有更新或已是最新版。

自动化测试优先覆盖状态转换、备份完整性、故障注入和恢复协议；真实工具集成测试在隔离用户目录或专用测试机上执行，避免修改开发者日常使用的 Agent 与配置。
